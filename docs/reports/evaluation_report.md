# 评估对比报告（更新于 2026-06-25）

## 1. 评估方法

### 评估指标

| 指标 | 定义 | 优化方向 |
|------|------|----------|
| Makespan | 总完工时间 `max(end) - min(start)` | ↓ 最小化 |
| 任务成功率 | `completed / total` | ↑ 最大化 |
| 资源利用率 | `busy_time / (makespan × num_arms)` | ↑ 最大化 |
| 约束违反次数 | 时间重叠 + 能力不匹配 | ↓ 最小化 |

### 评估协议

- **场景**: 6个MRTA-Benchmark场景（1p-6p）
- **种子**: seed=42-46（每个场景5个种子，共30次实验）
- **仿真后端**: PhysXOnlySimulator（纯物理计算 + MRTA旅行时间，无Vulkan渲染）
- **基准**: MILP最优（PuLP CBC求解器）
- **LLM**: DeepSeek Chat（替代mimo-v2.5，因长prompt超时）
- **旅行时间**: MRTA T_t矩阵
- **约束违反**: 0（大多数场景）

## 3. 数据分析

### 3.1 与MILP最优解的对比

- **平均比率**: 1.19x，系统整体接近MILP最优解
- **最优场景**: 2p（0.74x）和6p（0.94x），系统调度优于或接近MILP基准
- **最差场景**: 4p（1.59x），超出最优解59%

### 3.2 场景分析

- **1p（1.20x）**: 略超最优解20%，可接受范围
- **2p（0.74x）**: 系统表现优异，仅用最优解的74%时间完成任务
- **3p（1.33x）**: 超出最优解33%，受任务依赖和旅行时间影响
- **4p（1.59x）**: 超出最优解较多，复杂场景下调度难度上升
- **5p（1.33x）**: 与3p持平，超出最优解33%
- **6p（0.94x）**: 接近最优解，仅超时6%

### 3.3 成功率

- **平均成功率**: 80%
- **最优场景**: 6p（88%）
- **最差场景**: 3p（72%），受LLM任务分解质量影响

### 3.4 资源利用率

- **平均利用率**: 47%
- **范围**: 40% - 57%
- **分析**: 相比之前35%有显著提升，说明三机协同调度能力改善

### 3.5 约束违反

- **大多数场景**: 0次约束违反
- **说明**: 系统能够有效遵守时间、空间和资源约束

## 4. 结论

1. **平均性能接近最优**: 平均比率1.19x，说明系统整体接近MILP最优解
2. **DeepSeek Chat驱动有效**: 替代mimo-v2.5后，任务分解和代码生成表现稳定
3. **资源利用率提升**: 平均47%相比之前35%有显著改善，三机协同调度能力增强
4. **成功率有待提升**: 平均80%成功率，需要进一步优化LLM任务分解和代码生成质量
5. **PhysXOnlySimulator有效**: 在无Vulkan渲染的容器环境中，纯物理计算+MRTA旅行时间仍能提供可靠的仿真结果
6. **复杂场景挑战**: 4p场景的1.59x比率表明，工件数增加时任务调度难度上升
