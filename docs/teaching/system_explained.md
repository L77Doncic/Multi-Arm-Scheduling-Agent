# 多机械臂调度智能体 —— 通俗讲解

> 把你当成学生，我来给你讲清楚这个系统是怎么实现的。

---

## 1. 一句话总结这个项目

**你用自然语言告诉系统"帮我组装这些零件"，系统自动拆解任务、分配机械臂、生成控制代码、跑仿真、收集结果、调整策略，最后告诉你"做完了，用了多少时间，成功率多少"。**

就像你告诉一个项目经理"帮我把这100个零件组装好"，他自动拆解成具体工序，分配给不同工人，每个工人拿到自己的操作步骤，做完后他收集结果并改进下一次的安排。

---

## 2. 整体流程（流水线）

```
你的指令（自然语言）← 来自场景配置文件的 instruction 字段
       ↓
   ① 任务分解（拆解成小任务）
       ↓
   ② 资源分配（哪个机械臂做哪个任务）
       ↓
   ③ 代码生成（为每个机械臂生成控制代码）
       ↓
   ④ 仿真执行（在 Isaac Sim 里跑真实物理仿真）
       ↓
   ⑤ 结果验证（检查有没有违规）
       ↓
   ⑥ 反馈调整（根据结果调整下一次的策略）
       ↓
   ⑦ 输出指标（用时、成功率、资源利用率等）
```

这个流水线对应代码里的 `core.py` 文件中的 `execute_scheduling()` 方法。

## 2.1 系统怎么知道要做什么？—— 指令从哪来

**你的疑问：** 我跑实验时没有手动输入任何指令，系统怎么就自己开始跑了？

**答案：** 指令（instruction）是**预写在场景配置文件（JSON/YAML）里的**，不是你每次手动输入的。

### 实际运行流程

```bash
你运行：python scripts/run_simulation.py --scenario data/scenarios/1p_production_line.json
```

系统自动执行以下步骤：

```
1. 读取 1p_production_line.json
       ↓
2. 从 JSON 中提取 "instruction" 字段：
   "Execute a 4-station production line with 2 workpieces. 
    Workpieces flow through feed, transport, assembly, and inspection stations. 
    3 robot arms are available. Optimal makespan: 584.9s."
       ↓
3. 把这个 instruction 传给 SchedulingAgent.execute_scheduling()
       ↓
4. Agent 用 LLM（或模板规则）拆解成具体任务
```

### 代码对应

```python
# scripts/run_simulation.py 第172行
instruction = scenario_data.get('instruction', 'Execute assembly tasks')
```

- 如果配置文件里有 `instruction` 字段 → 用它
- 如果没有 → 用默认值 `'Execute assembly tasks'`

### 场景配置文件结构

```json
{
  "scenario": {
    "name": "MRTA-1p-ProductionLine",
    "instruction": "Execute a 4-station production line with 2 workpieces...",
    "stations": [...],
    "workpieces": [...],
    "robot_arms": [...]
  }
}
```

### 如果你想让系统做不同的事

1. **修改 JSON 文件里的 `instruction` 字段** —— 改成你想要的任务描述
2. **创建新的场景配置文件** —— 定义新的工位、工件、机械臂

## 3. 每一步详细解释

### ① 任务分解（Task Decomposition）

**做什么：** 把一段自然语言指令拆解成一个个具体的小任务。

**举个例子：**
- 你的指令：`"3个工件需要在4个工位组装，3个机械臂协作完成"`
- 分解后得到的任务列表：
  - 任务1：机械臂A从料仓取工件1放到工位1
  - 任务2：机械臂B对工位1的工件1进行组装
  - 任务3：机械臂C把组装好的工件1移到工位2
  - 任务4：机械臂A从料仓取工件2放到工位1
  - ...等等

**实现方式：**
- 如果有 LLM（大语言模型），就让 LLM 来拆解（更智能）
- 如果没有 LLM API，就用模板规则拆解（硬编码但可靠）
- 每个任务都有：ID、名称、描述、依赖关系、优先级、需要的机械臂能力

**依赖关系很重要：** 任务3必须等任务1和任务2都完成才能开始，这形成了一个"有向无环图"（DAG），系统按顺序执行。

---

### ② 资源分配（Resource Allocation）

**做什么：** 把每个任务分配给一个具体的机械臂。

**核心原则：**
- 能力匹配：机械臂必须有任务需要的能力（比如"pick"能力才能抓取）
- 负载均衡：不要让一个机械臂干太多活，其他的闲着
- 冲突解决：同一个机械臂不能同时做两个任务

**代码实现（`resource_allocator.py`）：**
```
对于每个任务：
    找到所有能力匹配的机械臂
    按照负载从低到高排序
    选负载最低的那个
    标记该机械臂为"忙碌"
```

**输出：** 一个映射表 `{"任务1": "arm_A", "任务2": "arm_B", ...}`

---

### ③ 代码生成（Code Generation）

**做什么：** 为每个机械臂生成一段 Python 控制代码，告诉它怎么一步步完成任务。

**核心概念：9个原子技能原语**

系统有9个基础动作，代码生成器会组合这些基础动作来完成复杂任务：

| 原语 | 作用 | 参数 |
|------|------|------|
| `move_to(x,y,z)` | 移动到目标位置 | 位置坐标 |
| `grip(force)` | 闭合夹爪抓取 | 抓取力 |
| `release()` | 打开夹爪释放 | 无 |
| `rotate(roll,pitch,yaw)` | 旋转末端执行器 | 旋转角度 |
| `linear_move(dx,dy,dz)` | 相对移动 | 相对位移 |
| `wait(duration)` | 等待 | 时间 |
| `check_sensor(type)` | 读取传感器 | 传感器类型 |
| `set_payload(mass)` | 设置负载质量 | 质量 |
| `set_compliance(x,y,z)` | 设置柔顺性 | 刚度 |

**举个例子：** 任务是"从位置(1,0,0)抓取工件放到位置(3,2,0)"

生成的代码可能是：
```python
def execute_task():
    move_to(1.0, 0.0, 0.5)   # 先移动到工件上方
    linear_move(0, 0, -0.3)   # 下降
    grip(20.0)                 # 抓取
    linear_move(0, 0, 0.3)    # 抬起
    move_to(3.0, 2.0, 0.5)   # 移动到目标位置上方
    linear_move(0, 0, -0.3)   # 下降
    release()                  # 释放
    linear_move(0, 0, 0.3)    # 抬起
```

**关键点：** 代码是**动态生成**的，不是从固定模板复制的。LLM 会根据任务描述、机械臂能力、当前场景参数来组合原语。

---

### ④ 仿真执行（Simulation Execution）

**做什么：** 在 Isaac Sim 物理仿真器里实际执行生成的代码。

**为什么用仿真：**
- 真实机械臂很贵，不能随便试错
- 仿真可以快速测试几百次
- 物理仿真验证抓取、放置是否可行

**执行流程：**
1. 加载场景（机械臂模型、工件、工位）
2. 按照依赖顺序执行任务（DAG 拓扑排序）
3. 每个任务的代码通过 `ArmInterface` 适配器执行
4. 适配器把原语调用转换成仿真器的动作

**代码执行的实际调用链：**
```
生成的代码 → ArmInterface → IsaacSimInterface → Isaac Sim 物理引擎
```

**容错机制：** 如果任务失败，系统会：
1. 记录异常
2. 判断异常类型（超时？碰撞？能力不足？）
3. 决定恢复策略（重试？跳过？换方案？）
4. 如果重试，还会根据失败原因**重新生成代码**

---

### ⑤ 结果验证（Result Validation）

**做什么：** 检查执行结果是否符合约束条件。

**检查内容：**
- 时间约束：任务是否在预期时间内完成？
- 空间约束：机械臂有没有碰撞？
- 资源约束：有没有超载？
- 依赖约束：任务顺序有没有错？

**验证结果：** `is_valid = True/False` + 具体违规信息

---

### ⑥ 反馈调整（Feedback Loop）—— 系统的"灵魂"

**做什么：** 这是整个系统最关键的部分。它形成了一个闭环：

```
执行结果 → 分析问题 → 调整参数 → 下一次执行
```

**调整的6个参数：**

| 参数 | 作用 | 调整规则 |
|------|------|----------|
| `timeout_adjustment` | 超时时间倍数 | 性能差时增加（×1.2） |
| `retry_count` | 重试次数 | 成功率低时+1 |
| `resource_weight` | 资源分配权重 | 过载时增加 |
| `priority_boost` | 任务优先级提升 | 频繁失败的任务提升 |
| `speed_factor` | 代码生成速度系数 | 失败率高时降低（×0.8，动作更慢更稳） |
| `force_factor` | 抓取力系数 | 失败率高时增加（×1.15，抓得更紧） |

**闭环工作原理：**
1. 每个任务执行后，结果送入 `FeedbackLoop`
2. `FeedbackLoop` 分析：成功率、耗时分布、错误模式
3. 生成调整建议
4. 调整参数应用到对应模块（资源分配器、异常处理器、代码生成器）
5. 下一个任务执行时，已经用上了新的参数

**举个例子：**
- 第1次执行：机械臂A抓取工件失败3次
- 反馈分析：失败率高，可能是抓取力不够
- 调整：`force_factor` 从1.0 → 1.15
- 第2次执行：代码生成时抓取力参数变为 `20 × 1.15 = 23`
- 结果：抓取成功率提升

**这就是"闭环"——系统的输出变成了下一次执行的输入，不断自我优化。**

---

### ⑦ 输出指标（Metrics）

**做什么：** 计算最终的性能指标。

| 指标 | 含义 | 计算方式 |
|------|------|----------|
| `makespan` | 总完成时间 | 最后一个任务结束 - 第一个任务开始 |
| `task_success_rate` | 任务成功率 | 成功任务数 / 总任务数 |
| `resource_utilization` | 资源利用率 | 所有机械臂忙碌时间 / (总时间 × 机械臂数量) |
| `constraint_violations` | 约束违规次数 | 同一机械臂时间重叠的次数 |

## 5. 关键设计思想

### 思想1：LLM 回退机制

系统设计了"智能模式"和"兜底模式"：
- 有 LLM API：用 LLM 做任务分解和代码生成（更智能）
- 没有 LLM API：用模板规则做任务分解和代码生成（可靠但不灵活）

这样即使没有 API Key，系统也能完整运行。

### 思想2：物理仿真

系统使用 Isaac Sim 4.5 作为唯一仿真后端：
- PhysX 物理引擎（重力、碰撞、关节）
- Franka Panda USD 机械臂模型
- Jacobian IK 逆运动学控制
- Omni Replicator 帧捕获

### 思想3：原子原语 + 动态组合

系统不提供固定的"抓取技能"、"放置技能"，而是提供9个原子原语，由代码生成器根据任务**动态组合**。

这就像乐高积木：系统提供基础积木块，你根据需要搭建不同形状，而不是给你一套固定的模型。

### 思想4：闭环反馈是核心

很多调度系统是"一次性"的：分配完就结束了。这个系统是"持续优化"的：
- 每次执行都收集反馈
- 反馈调整参数
- 下一次执行用新参数
- 系统越来越好

## 7. 一个完整例子

**输入：**
```
指令: "3个工件需要在4个工位组装，3个机械臂协作完成"
场景: 4个工位（工位1-4），3个工件（工件1-3），3个机械臂（arm_A/B/C）
```

**执行过程：**

| 步骤 | 动作 | 结果 |
|------|------|------|
| 1 | 任务分解 | 生成12个任务（每个工件4个操作） |
| 2 | 资源分配 | arm_A: 4个任务, arm_B: 4个任务, arm_C: 4个任务 |
| 3 | 代码生成 | 为12个任务各生成一段控制代码 |
| 4 | 仿真执行 | Isaac Sim 里3个Franka机械臂同时工作 |
| 5 | 结果验证 | 检查通过，无违规 |
| 6 | 反馈调整 | arm_B 稍慢，降低 speed_factor |
| 7 | 输出 | makespan=25.0s, success_rate=100% |

## 8. 总结

这个系统的本质是一个**自适应的多机械臂调度框架**：

1. **智能分解**：用 LLM 或规则把复杂任务拆成简单任务
2. **动态分配**：根据能力和负载自动分配机械臂
3. **代码生成**：用原子原语动态组合出控制代码
4. **真实仿真**：在 Isaac Sim 里验证物理可行性
5. **闭环优化**：根据结果自动调整策略，越来越好

就像一个会自我学习的项目经理，每次项目完成后都会总结经验，下次安排得更好。
